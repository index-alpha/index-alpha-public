# Create up to three science cards

Read the [definition](../../definition.md), [common workflow](../../../workflow.md),
and [image procedure](../../../images.md); they govern mode, writes, and recovery.

1. Resolve the exact actor/private Index and host-supplied run context/targets.
   Follow [setup](../../../setup.md) for initial private setup and card
   view/new ordering. Inherit the requested mode through the ordered pipeline.
2. Process at most three supplied qualified candidates. Reuse same-run primary
   source/HTML snapshots for drafting and OG extraction; refetch only when stale,
   missing, or needed to resolve a material gap. Batch exact `get_cards` lookups
   for defined custom IDs and recorded aliases before creation. Use the selection
   task's bounded ambiguity budget; never scan the whole Index or treat denial
   as absence. Reuse existing cards; defer unresolved identities.
3. Draft the definition's concise structure. Separate observation from interpretation, publication from acquisition dates,
   and processed imagery/artist concepts from photographs. Preserve uncertainty
   and provide full official article, asset, and consulted research references.
   Do not add AI-authorship labels or generic summary disclaimers.
4. Attempt one relevant image per card using the shared image procedure
   and existing snapshots. Retain available full collaborators credit, asset links, image type, and scientific caption.
   Do not search for affirmative reuse permission; honor explicit no-reuse notices.
   Record a useful text-only fallback for explicit no-reuse notices, missing assets, download, upload, or
   finalization fail. Reconcile uncertain card writes before fallback mutations.
5. Publish/reconcile using the definition's stable custom ID and common write
   contract. Confirm committed IDs/links and server `created_at` for +24h/+72h
   due times; use current versions/hashes, images, and revisions as platform
   evidence. Keep meaningful source links/evidence/credits in the card content
   and ordinary edit summaries. Pass receipts and known custom IDs in memory;
   persist only non-observable recovery facts in optional sparse `run.json`.
   Report proposals, existing items, shortfalls, successes, and fallbacks.
6. Pass exact created/changed cards, this definition, in-memory run context,
   source cache/evidence, inherited mode, and invocation deadline to shared
   fact-checking then formatting.
   The host records pipeline outcome; no score or grant changes belong here.

Stop at three cards, the invocation deadline, or an unresolved authorization/write
failure under the common workflow. Local drafts/uploads do not prove publication.
