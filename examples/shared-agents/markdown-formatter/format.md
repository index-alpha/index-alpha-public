# Format changed pages

Follow the [entry point](README.md), [style guide](style.md), [common rules](../../workflow.md)
and [completion preflight](../completion.md).

1. Reuse full same-run mutation receipts or read current Markdown/metadata;
   selected multi-page checks may use bounded `get_pages`. Read relevant history
   when needed for older/intervening work. Use matching
   in-memory/optional receipt evidence for prior style context or invisible
   no-change checks. Skip established completed scope; otherwise inspect changed
   Markdown or new standards. No source retrieval; report broken-looking links
   rather than replacing destinations.
2. Produce the smallest formatting-only diff. Preserve wording, claims, caveats,
   quotes, code, list/check states, table values, citations, anchors, images and
   credits. Leave uncertain constructs intact.
3. Inspect block structure; use preview if available and disclose preview limits.
   The same standard applied again should make no further style change. For a
   compliant page, record a scoped evaluation on its exact saved revision under
   [completion.md](../completion.md); matching established coverage needs no write.
4. In edit mode commit real style changes and removal of identifiable legacy
   administrative review/revision footers under common version/recovery rules.
   Preserve article citations, caveats and credits. Use a descriptive revision
   summary; never append a check log. Proven formatting/footer-only changes need
   no Signal score reset or reranking. On conflict recompute against latest
   content. No dummy edits. Report mode returns unsaved proposals only.
5. Pass actual checked/result versions, applied standard and preservation outcome
   in memory so review coverage can be reused. Save an optional receipt only for
   context/outcomes not reconstructible from platform evidence. If meaning cannot
   be preserved, do not edit; return the issue to its owner.

Return canonical links, changes/proposals, preview limits and unresolved work.
No-op responses can reference old revisions; do not attribute them to this run.
